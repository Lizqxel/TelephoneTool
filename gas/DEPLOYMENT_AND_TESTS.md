# 30分集計の反映手順と検証内容

## 反映するGAS

2つのプロジェクトに分離します。

| 出力ファイル | 貼り付け先 | 維持するトリガー |
|---|---|---|
| `exports/01_receiver_save.gs.txt` | 既存のフォーム受信・保存用プロジェクト | `processSubmissions`（1分おき） |
| `exports/02_dashboard.gs.txt` | CC第二ダッシュボードのプロジェクト | `autoRefresh`（既存間隔） |

受信・保存用の実装元は `call_statistics.gs` です。ダッシュボードの `autoRefresh` は元の更新処理へ戻します。
元のダッシュボードの `doGet`、`getCallHours`、名簿・シフト・会計処理、HTMLは保持します。
`dashboard_with_call_statistics.gs.txt` は旧ファイル名互換のため残しますが、現在はダッシュボード用コードだけです。

1. 受信用GASのコードを01の全文へ置き換え、既存のスクリプトプロパティ `TOKEN` と `FORM_ID` を維持します。
2. ダッシュボード用GASのコードを02の全文へ置き換えます。受信用コードを二重に残さず、既存のHTMLは維持します。
3. 受信用プロジェクトで `setupStatisticsData` を1回実行して非表示シートを準備します。
4. 必要な再承認は、受信用トリガーを作成したアカウントで行います。
5. アプリの「自分の集計を送信」で当日の保存済みデータを再送します。
6. 受信用プロジェクトで `processSubmissions` を実行するか、既存の1分おきの処理を待ちます。
7. 実行ログの `schemaVersion: 2`、`intervalSheet`、`intervalCount` と、アプリの「全員の集計」を確認します。

既存フォームが稼働している場合は、作り直しません。受信GASだけがフォームを読み、保存成功後に回答を削除します。
旧受信GASは30分データを保存せずに回答を削除するため、旧版を新しい受信用コードへ置き換える必要があります。
別プロジェクトのロックやスクリプトプロパティは共有されません。ダッシュボードと受信GASを同じフォームの読み取り担当にしないでください。

フォームが未設定の初回だけ `setup` を実行します。既存の受信用トリガーは再利用し、未登録の場合だけ1分おきのトリガーを追加します。
新しいフォームを作成した場合は、実行ログの `formResponseUrl`、`tokenEntry`、`dataEntry` をアプリへ反映します。
受信用プロジェクトに元からあった `processSubmissions` は削除しません。ダッシュボード側に誤って追加した受信用トリガーだけ、所有者が削除します。

`diagnoseStatisticsReceiver` は読み取り専用で、フォーム送信先URL・未処理回答数・新形式/対話時間あり回答数・非表示シートの有無を出力します。
共有トークンや回答本文はログへ出力せず、回答やシートの変更もしません。フォームURLとアプリの送信先が一致することを確認してください。
受信の一時エラーは回答を3時間まで保持して再処理します。TOKEN/FORM_IDが未設定の回は回答を処理・削除しません。

2つの全文txtの再生成は `build_integrated_gas.ps1 -OriginalPath <元のダッシュボードコードのパス>` で行えます。

ローカルのコードを更新しても、Google上のGASは自動更新されません。
全員の読み取りには、ログインしたGoogleアカウントの対象ファイルへの閲覧権限が必要です。

## データの意味

- 時間帯はCTIの「対応日時」基準、各30分の開始時刻以上・終了時刻未満です。
- 対話時間は「見込（新規・継続）＋対話有NG」のIP電話通話時間の合計秒数です。
- 従来の「応答時間」は全架電履歴のIP電話通話時間で、対話時間とは区別します。
- トスの定義は従来どおり、当日の新規見込候補と現在の見込ランクを照合し、管理番号ごとに最初の該当時間帯へ1件です。
- 全体・1人あたり平均は、選択範囲のコール数・対話数・対話時間が取得済みの人を対象にします。
  未送信・未判定の人数も表示し、0件を取得できた人は平均の人数に含めます。
- 1件あたり平均は「総対話時間÷総対話数」。対話0件は「—」です。
- 全日表示は各人の最終取得までの実績です。選択中の時間帯やグラフには取得途中の値を含みます。
- 履歴の取得に失敗した回は、直前の30分データとその取得日時を維持します。
- 保存済みの1時間データを30分に半分ずつ配分することはしません。

## 保存・互換性

新形式の送信は `schemaVersion: 2`、`observedAt` と取得時点までの全30分枠を含みます。
月別非表示シートのキーは日付・スタッフID・開始分です。
同じデータの再送は置換し、加算しません。古い取得日時の送信は既存値を上書きしません。
送信形式や数値が不正な場合は、セルを書き換える前に拒否します。
従来の1時間表はコール・対話・トスのみを更新し、nullは既存値を維持します。
非表示シートのnullは未取得を表す空欄として保存し、既知の0と区別します。
旧形式のクライアントは1時間表への送信を継続できます。

## ローカル検証

実際のGoogleフォーム、スプレッドシート、CTIへ接続せずに検証します。

```powershell
.\venv\Scripts\python.exe -m pytest tests/test_half_hour_statistics.py tests/test_call_statistics.py tests/test_call_statistics_clear.py tests/test_call_statistics_dialog.py tests/test_team_statistics.py tests/test_import_smoke.py -q --basetemp=logs/pytest-new-run
node --test tests/test_call_statistics_gas.cjs
```

`--basetemp` は実行ごとに新しい専用ディレクトリを指定してください。

| 対象 | 検証内容 |
|---|---|
| 時間境界 | 00:00、29:59、30:00、59:59、23:59、翌日へのタイマー |
| 集計 | 本人・当日だけ、通話ID重複、対話有無、0秒対話、未判定、トスの重複防止 |
| 保存 | 旧DB保持、未来枠を0にしない、再取得で置換、履歴取得失敗、古い取得結果の拒否 |
| 送信契約 | Pythonで生成した実ペイロードをGAS本体の検証関数へ渡す |
| GAS | 非表示シート作成、月別保存、ヘッダー、再送、別スタッフ、行拡張、共有トークン、ロック、失敗時の再処理 |
| 入力検証 | 負数、小数の件数、文字列数値、非有限値、重複枠、不完全な全日スナップショット、時差付き日時、バージョン |
| 読み取り | 非表示データ、未送信者、見出し不一致、不正値、重複キー、権限エラー、旧表の維持 |
| 表示 | 対話時間順、0件と未取得、加重平均、24時間以上の時間、ユニット絞り込み |
| コピー | 表と同じ並び・値・全体・平均、日付・時間帯・ユニット、タブ/改行を含む氏名 |
| グラフ | 同じ集計値の48枠、取得人数、実描画、日本語フォントでの画像出力 |
| 送信確認 | 1時間表だけ更新されている場合に、30分データ反映済みと誤表示しない |
| GASの分離 | 旧受信GASの対話時間消失を再現、修正版の保存後削除、ダッシュボードからフォームを開かないこと、全文txtの一致 |
| 設定・診断 | 既存受信トリガーの再利用、未登録時だけ追加、TOKEN/FORM_ID欠落時の回答保持、秘密を出さない読み取り専用診断 |

画像は `logs/team_statistics_ranking_preview.png` と `logs/team_statistics_trend_preview.png` に出力します。
Google上の権限・フォーム設定・時間トリガーの実行は、GAS反映後に確認する項目です。
