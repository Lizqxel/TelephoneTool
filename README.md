## 📋 概要

TelephoneToolは、コールセンター業務の効率化を目的として開発されたWindows専用のGUIアプリケーションです。PySide6を使用して構築されており、顧客情報の管理、CTIフォーマットの生成、NTT西日本の提供エリア判定など、コールセンター業務に特化した機能を提供します。

## ✨ 主な機能

### 🎯 コア機能
- **顧客情報入力・管理** - 構造化された顧客データの入力フォーム
- **CTIフォーマット生成** - コールセンター標準フォーマットの自動生成
- **クリップボード監視** - 自動的なデータ取得・転記機能
- **Google スプレッドシート連携** - データの自動転記・同期（未実装）

### 🌐 提供エリア判定機能
- **NTT西日本 提供エリア検索** - 住所から光回線の提供可否を自動判定
- **ワンクリック検索** - 簡単操作での提供判定実行
- **詳細エラー表示** - 判定失敗時の詳細なエラー情報表示

### 📞 CTI連携機能
- **電話番号監視** - 着信番号の自動検出
- **フォーマット自動生成** - 着信情報に基づくフォーマット作成
- **リアルタイム更新** - 通話状況に応じた動的な情報更新

### 時間帯別の通話集計

上部の「集計表」で保存した日別の表を確認でき、表の中の「今すぐ集計」で毎時00分・30分を待たずに当日分を取得・送信できます。
自動集計は起動後の初回取得と毎時00分・30分に実行し、結果をスプレッドシート「CC第二コール管理」の
「コール集計打ち込み用_M月」へ送ります。集計表から停止・再開できます。
集計の保存後に、CTIの架電履歴の「クリア」を実行します。TelephoneToolの保存済み集計は保持します。
集計・保存に失敗した場合や、履歴を取得しなかった回はクリアしません。クリアだけ失敗した場合は、集計済みの値を表示したまま警告します。

- **コール**：架電履歴の当日の件数を時間帯別に数えます。集計開始前の分や、通話0秒・留守も含みます。
- **対話**：見込（新規・継続）＋対話有NGの件数を架電履歴から数えます。NGは「現アナNG」「多重留守NG」を対話無、「架電禁止NG」「非勧奨登録NG」を禁止（CTIは架電結果「禁止」として集計）、それ以外の詳細をすべて対話有として数えます（`services/call_statistics.py` の `NG_WITHOUT_DIALOGUE_DETAILS`・`NG_RECORDED_AS_PROHIBITED`。CTIの個人別コール集計の 対話有NG／対話無NG／禁止件数 と一致）。架電結果詳細が読めないNGや未知の架電結果がある時間帯は「未判定」にして結果名を表示します。
- **トス**：当日の見込のうち、見込検索のランクが「トス」のものです。架電履歴にはランクが無いため、見込検索を裏で検索し、管理番号で突き合わせます。同じ見込への再架電は最初の時間帯に1件だけ数えます。
- **応答時間**：架電履歴の「IP電話通話時間」を「対応日時」の時間帯別に合計します。同じ履歴を再取得しても重複加算しません。
- **新規見込・対話NG**：履歴に明記された結果から過去分も集計し、判別できない場合は取得済みの上部累計の差分を使います。対話NGは「対話有NG」です。
- 表は当日の最初のログの時間帯から表示します。最後に集計した時刻の時間帯は、取得状態に「途中（HH:MM時点）」と出し、その時刻までの件数であることを示します（当日のみ）。
- **過去日**：集計表の日付を過去日にすると、ボタンが「この日を集計」になり、その日の架電履歴を集計して保存し、シートのその日の表へも送ります。
  上部の累計（有効コールなど）は当日の値なので使いません。トスは今の見込検索のランクで判定します。
  シートへは、その日の23:59:59時点の結果（30分枠は48枠すべて）として送ります。
- 集計中（自動集計を含む）も日付を変えて他の日を見られます。集計表のボタンで始めた集計が終わると、集計した日の表に戻ります。
  集計中は「中止」ボタンで止められます。
  中止してもCTIの検索日時・商材は元に戻し、保存済みの値は残します（その回の結果は保存・送信しません）。
- 取得間隔が時間帯をまたいだ場合や、CTI再起動・リスト変更・累計のリセットを検出した場合は、差分を推測で割り振らず、取得状態に表示します。

CTI側の条件（満たさない回はスキップし、保存済みの値を維持して次回に取り直します）：

- 架電履歴・見込検索のスタッフ一覧で本人にチェックが入っていること。他の人にチェックがあっても、画面下部のログイン名で本人の行だけを集計します。
- 架電履歴の検索日時は、集計する日の00:00:00～23:59:59に変えてから検索し、読み終えたら元の日時に戻します
  （長い期間のままだと全ページを読むのに数分かかるため。過去日の集計にも使います）。
  日時欄は別プロセスへのメッセージでは値を渡せないため、CTIのプロセス内に一時領域を確保して値を書き、
  利用者が日時を変えたときと同じ通知を日時欄へ送ります（`services/cti_remote.py`）。
  変えられなかった場合は今の検索日時のまま集計し、その場合は検索日時が集計する日の00:00:00～23:59:59を含んでいる必要があります。
- 架電履歴の電話番号欄が空であること。
- CTI起動後に架電履歴・見込検索のタブを一度開いていること（開くまで画面の部品が作られません）。
- 架電履歴を表示中の回は検索をしません。見込検索を表示中の回は、表示中の結果をそのまま使います。
- ログイン名はステータスバーをMSAAで読みます（最小化中も読める想定。読めない場合はUI Automationで読み直します）。
- 架電履歴は50件ごとのページに分かれるため、「次へ」で全ページを読み、「検索結果件数」と件数を照合してから1ページ目に戻します。
  各ページは、検索結果件数から分かる行数どおりに読めれば1回だけ読みます（合わないときは、同じ内容が2回続くまで読み直します）。
- 表はセルを1つずつ読むため、集計に使う列（対応日時・対応スタッフ・架電結果・架電結果詳細・IP電話通話時間・管理番号・通話ユニークID、
  見込検索は管理番号・スタッフ・ランク）だけを読みます。電話番号などの列は読みません（287件の日で約80秒→約25秒）。
- 架電履歴の「商材」が「-」（未選択）だと、CTIは架電結果詳細（現アナNGなど）を空欄で返し、列も表示しません。
  このため商材が未選択のときは、検索の間だけ架電画面の「商材」（今のリストの商材）と同じ名前の選択肢を選び、
  読み終えたら「-」へ戻します。同じ名前が無ければ、選べる商材が1つだけのときにそれを選びます
  （CTIで利用者が選んだときと同じ通知を送ります。切り替え時にCTIは履歴の種類を「架電履歴」に戻します）。
  担当者が選んだ商材はそのまま使います。どれも選べない場合は選ばず、詳細の無いNGは未判定にします。
  商材を選ぶと、その日に別の商材のリストへ架電した分は架電履歴に出ません。
  なお、扱う商材が1つのアカウントでは、CTIが起動時に商材を入れて欄を固定するため、この処理は動きません。

スプレッドシートへの送信は、ログイン不要の送信用Googleフォームを経由します（会社の設定でGASのウェブアプリを「全員」に公開できないため）。
このスプレッドシートは開くだけで数十秒〜100秒近くかかるため、別プロジェクトの受信用GASの `processSubmissions` が、1分ごとに届いた送信をまとめて1回開いて書き込みます（同じ人・同じ日は最新の送信だけ）。
書き込むのは「日付の表 × 名前の行 × H時台」のコール・対話・トスのセルです。
毎回その日の全時間帯を送るので、再送しても重複しません。トークンを含む回答は書き込み後にフォームから削除します。
送信先は `services/call_statistics_sheet.py` の `DEFAULT_FORM`（または settings.json の `callStatisticsSheet`）、
トークンは既存の `googleFormPosting.tokenValue` を使うため、各PCで追加の設定は不要です。
フォームは書き込み結果を返さないため、シートに枠が無い時間帯（例：9時台）や名前が見つからない場合などは、Apps Scriptの「実行数」のログで確認します。

GAS側の初回設定：スクリプト プロパティに `TOKEN` を登録し、エディタで `setup` を実行して権限を承認します。
送信用フォームと非表示シートを準備し、ツールに設定する `formResponseUrl`・`tokenEntry`・`dataEntry` が実行ログに出ます。
`setup` は受信用の既存 `processSubmissions` トリガーを再利用し、未登録の場合だけ1分おきのトリガーを追加します。
書き込み結果やエラーは、受信用プロジェクトの「実行数」で `processSubmissions` のログを確認します。

#### 全員の集計（スプレッドシートの表示）

上部の「全員の集計」で、スプレッドシートの日付ごとの表（全員分の日計・10時台〜20時台のコール・対話・トス）を表示します。
初回だけ「Googleでログイン」を押し、シートを開ける社内のGoogleアカウントでログイン・許可します。
以後は `%LOCALAPPDATA%\TelephoneTool\google_token.json` のログイン情報で、開くたびと5分ごとに読み直します（読み取りのみ）。
GPユニットで絞り込め、自分の行は色付きで表示します。表の最後にはシートの「合計」行をそのまま出します
（ツールでは足し直さず、人数・30分集計の対象にも数えません。全員分の合計なので、GPユニットで絞り込んだときは出しません）。

「30分集計・ランキング」では、取得済み全日または00:00〜24:00の30分枠を選び、氏名・コール数・対話数・対話時間を対話時間の降順で表示します。
対話時間は「見込（新規・継続）＋対話有NG」に該当する履歴のIP電話通話時間です。全履歴の応答時間とは別に集計します。
全体・1人あたり平均は、コール数・対話数・対話時間の3項目が取得済みの人を対象にし、対象人数と未取得/未判定人数も表示します。
1件あたり平均は総対話時間÷総対話数です。対話0件は「—」。未取得を0として扱いません。
「表示内容をコピー」で、日付・GPユニット・時間帯・順位順の表・全体・平均をタブ区切りテキストでコピーできます。
「30分ごとの推移」では、選択日・GPユニットの対話時間・対話数・コール数を切り替えて表示します。空欄は未取得、取得途中の枠は途中実績です。
従来の1時間表は「従来の1時間集計表」タブで表示できます。

30分データは、フォーム受信用の `gas/call_statistics.gs` が非表示の月別シート `通話集計データ_YYYY-MM` を自動作成して保存します。
保存列は日付・スタッフID・氏名・部署・GPユニット・開始分・コール数・対話数・トス数・対話時間（秒）・取得日時です。
日付×スタッフID×開始分で置換し、古い取得結果では上書きしません。旧形式のクライアントも引き続き1時間表へ送信できます。
受信用GASを `gas/exports/01_receiver_save.gs.txt` の全文へ置き換え、既存フォームの `TOKEN`・`FORM_ID` と既存の1分おきの `processSubmissions` トリガーを維持します。
受信用プロジェクトで `setupStatisticsData` を1回実行します（フォームが未設定の初回だけ `setup`）。
ダッシュボード用GASは `gas/exports/02_dashboard.gs.txt` の全文へ置き換え、既存の `autoRefresh` トリガーを維持します。`autoRefresh` は元の更新処理だけを行い、フォームは読みません。
フォーム受信は別プロジェクトの受信用GASだけに担当させます。同じフォームを複数プロジェクトで読み取って回答を削除しないでください。
受信用の `diagnoseStatisticsReceiver` は、フォーム送信先URL、回答の形式、対話時間を含む回答の件数、非表示シートの有無を読み取り専用で確認します。共有トークンと回答本文は出力しません。
貼り付け手順は `gas/exports/README.txt` にあります。`gas/dashboard_with_call_statistics.gs.txt` は旧ファイル名互換のため残していますが、現在の内容はダッシュボード用のみで、受信処理は含みません。
旧DBの1時間データから30分データは推測生成しません。旧データは保持し、当日の履歴を再取得できた時点から30分データを保存します。
読み取りは30分データを先に取得し、接続待ち10秒・応答待ち120秒を上限にします。
従来の1時間表だけが時間切れになっても、取得できた30分実績を表示します。その場合、名簿が未取得のため対象人数は30分データ受信済みの人だけであることを明示します。

Googleログインには、Google Cloudで作ったOAuthクライアント（種類「デスクトップアプリ」、同意画面「内部」、Google Sheets APIを有効化）が必要です。
リポジトリが公開のため、ダウンロードしたJSONを `google_oauth_client.json` としてリポジトリ直下に置き（gitignore済み）、ビルド時にexeへ同梱します。

通話時間が数値だけの場合は秒として集計します。CTIの表示単位が分の場合は集計表で変更できます。
データと集計設定は `%LOCALAPPDATA%\TelephoneTool\call_statistics.sqlite3` に保存され、再起動後も残ります。
TelephoneToolが終了している間は自動取得しません。

## 🚀 インストール方法

### 前提条件
- Windows 10/11 (64bit)
- Python 3.8 以上
- Google Chrome ブラウザ（提供エリア判定機能使用時）

### 1. リポジトリのクローン
```powershell
git clone <repository-url>
cd TelephoneTool
```

### 2. 仮想環境の作成（推奨）
```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

### 3. 依存関係のインストール
```powershell
pip install -r requirements.txt
```

## 📖 使用方法

### 基本的な起動方法
```powershell
python main.py
```

### モード選択
アプリケーションは以下のモードで動作します：
- **簡単モード** - 基本的な機能のみ
- **標準モード** - 全機能利用可能

### 提供エリア判定の使用方法
1. 顧客情報入力フォームに住所を入力
2. 「提供エリア判定」ボタンをクリック
3. 自動的にNTT西日本サイトにアクセスして判定実行
4. 結果がフォーマットに自動反映

### CTIフォーマット生成
1. 必要な顧客情報を入力フォームに記入
2. 「フォーマット生成」ボタンをクリック
3. 生成されたフォーマットをクリップボードにコピー

## 🐛 トラブルシューティング

### よくある問題と解決方法

#### 1. WebDriverエラー
```
selenium.common.exceptions.WebDriverException
```
**解決方法**: Chrome ブラウザを最新版に更新してください。

#### 2. 提供エリア判定が失敗する
**解決方法**: 
- インターネット接続を確認
- NTT西日本サイトのアクセス可否を確認
- ログファイル（app.log）でエラー詳細を確認
